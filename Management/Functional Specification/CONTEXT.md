# Functional Specification Agent — CONTEXT.md

## תפקיד הסוכן
סוכן האפיון אחראי על כתיבה ועדכון של מסמך האפיון הפונקציונלי של מערכת One.
המסמך מתאר את המערכת לפרטיה — ארכיטקטורה, תהליכים, מסכים, DB, APIs, ואלגוריתמים.

## Session Start — מה לקרוא בהפעלה
1. `CONTEXT.md` (קובץ זה)
2. `CHANGES-QUEUE.md` — שינויים שסוכנים אחרים דיווחו מאז העדכון האחרון
3. `functional-spec.md` — המסמך הנוכחי (לפחות תוכן עניינים)
4. `CLAUDE.md` בתיקייה הראשית — סקירת מערכת
5. `Management/claude-working-guidelines.md` — כללי עבודה

## CHANGES-QUEUE — מנגנון עדכון
סוכנים אחרים מדווחים על שינויים מהותיים ב-`CHANGES-QUEUE.md`.
בכל הפעלה:
1. **קרא** את ה-queue
2. **עדכן** את `functional-spec.md` בהתאם (קרא קוד/CONTEXT אם צריך פירוט)
3. **נקה** את הרשומות שטופלו מה-queue
4. אם ה-queue ריק — אין שינויים ממתינים, אפשר לעבוד על הרחבות

## מקורות מידע
- `CLAUDE.md` בתיקייה הראשית — סקירת מערכת כללית

## כללי עבודה
1. המסמך נכתב בעברית (מונחים טכניים באנגלית)
2. מבנה: מהכללי לפרטני — סקירה → מערכות → תתי-מערכות → פרטים
3. כל שינוי במערכת צריך לבוא לידי ביטוי באפיון
4. לא להמציא — רק לתעד מה שקיים בפועל בקוד ובסוכנים
5. להצליב מול קוד בספק — CONTEXT files יכולים להיות לא מעודכנים
6. מסכי UI מתועדים עם תיאור שדות, מצבים, ואינטראקציות
7. דיאגרמות ב-Mermaid syntax (נתמך ב-Markdown)
